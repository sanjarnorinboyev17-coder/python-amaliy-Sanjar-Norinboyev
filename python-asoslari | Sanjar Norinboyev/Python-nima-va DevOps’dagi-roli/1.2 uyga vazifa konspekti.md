# 1. Python interpretatorlari

Python dasturlari bevosita protsessor tomonidan emas, balki Python interpretatori
orqali bajariladi. Interpretator Python kodini o'qiydi, uni bajaradi va dastur
natijasini qaytaradi. Bir xil Python tiliga mos bo'lsa ham, implementatsiyalar
ichki tuzilishi va ishlash tezligi bilan farqlanadi.

CPython Python tilining rasmiy va eng ko'p ishlatiladigan implementatsiyasi bo'lib,
C tilida yozilgan. U Python kodini bytecode'ga aylantirib, uni virtual mashinada
bajaradi. CPython keng kutubxona ekotizimiga, yaxshi hujjatlarga va ko'p sonli
uchinchi tomon paketlariga ega. Uning asosiy cheklovi Global Interpreter Lock
(GIL) bo'lib, bir jarayondagi Python threadlari CPUga bog'liq vazifalarni to'liq
parallel bajara olmaydi. Shunga qaramay, I/O, web va DevOps avtomatlashtirishida
CPython amaliy standart hisoblanadi.

PyPy Python tilining yana bir implementatsiyasi bo'lib, JIT (Just-In-Time)
kompilyatoridan foydalanadi. JIT ko'p marta takrorlanadigan Python kodini ish
vaqtida mashina kodiga optimallashtirishi mumkin. Shu sababli uzoq ishlaydigan
va CPUga bog'liq dasturlarda PyPy CPython'dan tezroq bo'lishi ehtimoli bor.
Biroq ayrim C extensionlar bilan moslik cheklanishi, ishga tushish vaqti hamda
xotira sarfi ko'proq bo'lishi mumkin.

Boshqa implementatsiyalarga Jython (Java Virtual Machine uchun), IronPython
( .NET uchun) va MicroPython (mikrokontrollerlar uchun) kiradi. Tanlov loyiha
talabiga bog'liq: umumiy DevOps skriptlari uchun CPython, uzoq ishlaydigan
hisoblashga boy servislar uchun esa PyPy sinab ko'rilishi mumkin.

# 2. Muhit vositalari taqqoslanishi

| Vosita | Afzalliklari | Kamchiliklari |
| --- | --- | --- |
| `venv` | Python bilan birga keladi; yengil; qo'shimcha o'rnatish talab qilmaydi | Dependency resolver va lock fayli yo'q; muhitni boshqarish qo'lda |
| `virtualenv` | Eski Python versiyalarida ham ishlaydi; tez; moslashuvchan | Alohida paket o'rnatish kerak; dependency boshqaruvi o'zida emas |
| Poetry | `pyproject.toml` va lock fayli bilan dependencylarni aniq boshqaradi; build va publish imkoniyati bor | O'rganish va sozlash murakkabroq; qo'shimcha dastur o'rnatiladi |

Ushbu loyiha uchun `venv` tanlandi, chunki topshiriq aynan `python3 -m venv`
buyrug'idan foydalanishni talab qiladi.

# 3. Subparser CLI

`1. Uyga vazifa.py` fayli `start` va `stop` buyruqlarini qabul qiladi:

```bash
python "1. Uyga vazifa.py" start
python "1. Uyga vazifa.py" stop
```

Har bir buyruq `service_status.txt` fayliga xizmat holatini yozadi. Boshqa fayl
uchun global parametrdan foydalanish mumkin:

```bash
python "1. Uyga vazifa.py" --state-file /tmp/demo-status.txt start
```

# 4. `requirements.txt`ni yangi muhitda sinash

Mavjud muhitdan dependencylar quyidagicha saqlandi:

```bash
python -m pip freeze > requirements.txt
```

Yangi muhitda quyidagicha tekshirildi:

```bash
python3 -m venv .venv-homework
source .venv-homework/bin/activate
python -m pip install -r requirements.txt
python -c "import requests; print(requests.__version__)"
deactivate
```

Natija: `requests` va uning dependencylari xatosiz o'rnatildi, import ham
muvaffaqiyatli bajarildi.

# 5. Crontab sinovi

CLI'ni har 5 daqiqada ishga tushirish uchun namunaviy yozuv:

```cron
*/5 * * * * /home/sanjar/sanjar-amaliy-uyga\ vazifa/python-asoslari\ \|\ Sanjar\ Norinboyev/Python-nima-va\ DevOpsdagi-roli/.venv/bin/python "/home/sanjar/sanjar-amaliy-uyga vazifa/python-asoslari | Sanjar Norinboyev/Python-nima-va DevOps’dagi-roli/1. Uyga vazifa.py" start >> /tmp/python-cli.log 2>&1
```

Amaliy qiyinchiliklar:

- crontab interaktiv terminaldagi `PATH` va virtual muhitni avtomatik meros
  qilib olmaydi;
- shu sababli Python executable'ning to'liq yo'li ko'rsatilishi kerak;
- papka nomidagi bo'sh joy, `|` va apostrof cron yozuvida quotingni
  murakkablashtiradi;
- log fayliga to'liq yo'l berish va cron xatolarini alohida tekshirish kerak.

DevOps muhitida bunday vazifa uchun yo'llarni soddalashtirish, wrapper Bash
skriptidan foydalanish yoki systemd timer tanlash ishonchliroq bo'lishi mumkin.
